# 目录与端口运行配置协议

## 操作与兼容

“目录与端口”显示当前文档路径、配置文件路径及四项服务端口。路径只读；目录模式下拉框提供共享目录／设备专有目录两种模式。批量操作只覆盖勾选字段，未勾选字段保留每台设备原值。有效配置可直接点击“应用”，无需先点击“预览变化”；预览是可选步骤。输入修改后立即重新校验，“应用”始终提交当前值，端口错误会直接显示；加载或提交期间禁用“应用”。旧设备和失败设备不会阻断其他设备。

弹窗沿用项目表单字体、控件和主题样式。仅保留底部“关闭”按钮，Esc 和点击遮罩也可关闭；从弹窗内拖到遮罩上松手不会误关闭。目录下拉框展开时，Esc 先收起下拉框。Tab 在弹窗内循环，关闭后恢复原焦点；已发起的操作由设备自行完成。内容区域滚动，底部操作按钮保持可见。

能力声明是可选的。设备 `/api/capabilities` 的 `features.runtimeSettings = true`、`apis.runtimeSettings.version = 1` 用于声明能力；已有迁移版本没有该声明时仍实际探测接口。只有接口明确返回 404／405／501，且能核实设备在线和身份，才判定不支持；连接失败、超时和迁移期间 503 均不能判成旧设备。

## 设备接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/runtime_settings/get` | 读取当前配置和路径 |
| GET | `/runtime_settings/status` | 查询实际活动状态和最后结果 |
| POST | `/runtime_settings/apply` | 提交一次配置修改 |

这些接口使用 `ok` 字段，不能按普通 OpenAPI 的 `code = 0` 解析。状态新增可选 `deviceid`；缺失时在同一地址读取设备信息核实身份。状态中的 `configured`、`active`、`bound`、`pending` 含义不同，直连和中控确认成功时使用实际绑定端口（缺失时兼容 `active`），不能仅以已写入配置文件判断成功。

每台设备必须提交自己的 `expected_revision` 和完整四端口：

```json
{
  "expected_revision": 12,
  "settings": {
    "port": 50152,
    "udp_port": 50153,
    "webdav_port": 0,
    "log_port": 0
  },
  "use_device_directory": true
}
```

切入设备专有目录才携带 `use_device_directory: true`；迁回共享目录才携带 `prepare_downgrade: true`。纯端口变更不携带目录动作，也不发送两个值为 false 的动作字段。API 端口必须为 10000–65535；UDP、WebDAV、独立日志端口可为 0，否则也必须为 10000–65535。三个非零 TCP 端口不可重复，UDP 可与 TCP 同号。

版本冲突根据 `ok: false` 和实际错误识别；既有设备可能返回 HTTP 400，中控预检返回 409。界面提示刷新后重试，不自动覆盖较新的配置。

## 单次提交和结果确认

直连和中控在发送保存前记录设备身份、旧访问地址、目标端口、目录模式和操作信息。保存只发送一次；响应丢失、服务重启、断线或关闭页面后只继续查询，不自动重放。设备端 worker 负责完成目录与端口修改及后续启动。

直连和中控每轮查询后间隔 2 秒，最多查询 5 分钟。身份、操作标识（响应丢失时使用预期版本）、版本、最终可用状态、目录模式和绑定端口全部匹配后才确认成功。匹配操作的失败／回滚结果显示实际错误；其他旧操作结果不能用于当前操作。5 分钟仍未确认显示“结果未确认”，保留“继续查询”，不推断失败或回滚。

直连和中控已知正在迁移或结果未确认时暂停新的文件写入和脚本启动。读取失败应保留错误或已有列表，不把暂时不可用显示为真实空目录。完成后刷新文件及相关连接。文件读取失败时按需探测运行状态，以识别外部发起的迁移；失败响应不会清空已有文件列表。

云控网页和 VSCode 云控模式仅发起一次请求，发出后显示“已发起配置修改”。不等待设备 HTTP 回包或最终结果，不轮询、不持久化待确认任务、不提供“继续查询”，也不因客户端的迁移记录拦截后续操作。无法发送请求时显示发送错误；设备端完成后按现有流程重新连接云控。需要查看配置时由用户手动刷新。

## 传输适配

- VSCode 直连记录旧、新端口，重开后核实同一设备并继续查询；确认后更新原设备记录。即使保存期间切换到中控视图，也更新持久化直连地址。
- 中控后端持久化操作并独立收尾，浏览器关闭不影响查询。确认可达地址属于同一设备后更新访问地址，保留设备 ID、名称、分组和访问映射；发布刷新事件，重建文件、日志及远控连接。
- 云控复用 `control/http`。每台设备、每次请求使用独立请求 ID；代理参数带 `timeoutMs`，不能把批量设备共用的首个响应当作全部结果。设备通过 UDID 重新上线，客户端按 `sys.port()` 读取活动 API 端口。

## 扫描与零端口

VSCode 的 `xxtouch.device.discoveryPorts` 和中控的 `discovery.broadcast.ports` 均默认为 `[46953]`，接受去重后的非空整数列表 1–65535，不允许 0。手动、启动、周期广播使用同一目标端口列表，中控 UDP 接收端口独立配置。中控发现请求省略 `ports` 时使用中控配置；多端口回包按设备身份合并。

修改设备 UDP 端口不会自动修改或保存中控、VSCode 的 UDP 扫描端口列表，扫描目标由用户手动配置。UDP 为 0 时不尝试恢复 UDP 发现，仍可手动添加和通过中控 HTTP 网段扫描导入。云控使用设备主动连接，不新增 UDP 扫描。

WebDAV、独立日志为 0 不影响 API 文件接口和 SSE 日志。扩展遇到临时 SSE 错误继续重试 SSE；只在明确不支持 SSE 时探测实际 `log_port` 并使用旧 WebSocket。字段缺失才使用 46957，值为 0 时不连接独立日志服务。

## 云控客户端副本

设备代理脚本的两个维护位置为 `device-client/open-cloud-control-client.lua` 与 XXTouch 仓库的 `layout/var/mobile/Media/1ferver/bin/open-cloud-control-client.lua`。本次核对两份内容一致，均已使用运行时主目录及 `sys.port()`，无需重复修改。

浏览器不保存待确认记录，页面重开后不恢复或查询旧操作。服务连接对象替换时销毁旧监听并创建新服务。批量表单并发上限沿用现有批量操作的 5 台。
